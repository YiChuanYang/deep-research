# RAG 第一、二阶段提速实测

日期：2026-11-17。使用已保存的 Web RAG 批次 `20261116T153227Z-e085d741`，原网页、报告和旧评测分数保持不变。这里只做局部性能回放，没有重新运行 20 题完整研究。

## GPU 与本地计算

机器为 GTX 1650 Ti，4GB 显存，驱动 592.82。原项目环境是 `fastembed 0.9.1 + onnxruntime 1.32.0`，没有 CUDA 执行器；已通过 uv 切换为 `fastembed-gpu 0.9.1 + onnxruntime-gpu 1.26.0`，并安装 CUDA 12 / cuDNN 9 DLL。实际模型会话验证为 `CUDAExecutionProvider, CPUExecutionProvider`，真实编码成功。

使用 DR-002 已保存语料等距抽取 64 个文本块，模型仍是 `BAAI/bge-small-zh-v1.5`，输出 512 维。CPU/GPU 均在同一新运行时测试，CPU 线程数 2；模型初始化和预热不计入下表，每项重复两次，列中位数。

| 批大小 | CPU 编码 | GPU 编码 |
|---|---:|---:|
| 8 | 6.145 秒 | 0.489 秒 |
| 16 | 7.098 秒 | 0.496 秒 |
| 32 | 6.093 秒 | 0.571 秒 |

批大小 16 时 GPU 约为 CPU 的 14.3 倍速度。不同批大小下向量相对第一组 CPU 输出的最小余弦相似度大于 0.999999999998；不是逐位完全相同。8 和 16 的差别很小，样本数有限，因此保留默认批大小 16，没有盲目增大到 32。

同一份 781 块语料、分词均已预热：重复构建 BM25 并评分平均约 35.98 毫秒，复用索引后约 2.11 毫秒，评分数值通过一致性检查。这个优化节省的是毫秒，主要性能收益仍来自向量编码和重排。

原始数据：[CPU/GPU 与 BM25 基准](../evals/runs/rag-speed-28aa0ffa123b/benchmark.json)。

另用默认 `embedding_device=auto` 实际执行 64 块索引和两次检索：无降级，生成 6 条选段，重复检索结果一致，第二次命中查询向量和 BM25 缓存。整个局部流程约 2.34 秒，包含初始化和首次中文分词加载，不包含远程重排或报告生成。

原始数据：[真实集成回放](../evals/runs/rag-integration-138d1f1798ab/integration.json)。

## 精简重排

最终版本对同一组 16 个候选、相同任务和当前配置模型，分别测试带理由与只输出分数，各两次，交替执行顺序。

| 题目 | 带理由耗时 | 精简耗时 | 带理由最终成功 | 精简最终成功 |
|---|---:|---:|---:|---:|
| DR-002 RAG 流程 | 平均 13.73 秒 | 平均 4.79 秒 | 2/2 | 2/2 |
| DR-020 消息确认 | 平均 24.53 秒 | 平均 5.83 秒 | 1/2 | 2/2 |

DR-020 带理由的两次执行都触发格式修复，其中一次最终仍是 JSON 错误，因此 24.53 秒包含一次失败执行，不能称为成功结果的公平速度比。DR-002 两组都成功，精简格式约减少 65.1% 耗时。样本很少，不能据此断言长期修复率已降到零。

**评分不等价。** DR-002 每组配对中有 9/16 个分数不同；DR-020 唯一成功的理由模式保留 11/16 个分数至少为 2 的候选，精简模式两次都保留 16/16 个。检查候选可见精简模式也提高了目录等背景片段的分数，过滤可能更宽松。因此本轮能确认局部提速，尚未证明报告质量保持。保留 `RERANK_INCLUDE_REASON=true` 作为可切换对照。

本轮还将评分模板默认 0 改成 null 占位，并明确按“当前任务”评分，而非要求每个片段回答整个研究主题；旧实验中的统一分数现象提示模板可能影响判断，但没有单独消融，不能宣称已证明根因。类型校验仍拒绝 null，必须得到完整的 0～3 整数分数。

最终原始数据：[DR-002](../evals/runs/rag-speed-8cacd1672468/benchmark.json)、[DR-020](../evals/runs/rag-speed-c4e2be977f19/benchmark.json)。其他 `rag-speed-*` 目录包含开发过程中早期模板或诊断试验，不与这张最终表混算。
