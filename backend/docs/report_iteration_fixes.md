# 报告反思边界修复与验证

本轮修复基于 `5d7faa2`。保留现有 LangGraph 节点、业务类型与检查点，不增加另一套执行引擎或新的模型依赖。

## 修改和原因

| 位置 | 修改 | 目的 |
|---|---|---|
| `services/review_protocol.py` | 模型协议拆为 revisions（最多 2 项）和 research_gaps（最多 1 项），再转换为原 ReportReview | 把“已有材料修订”和“需要外部材料”的参数分开；数量上限直接出现在工具 Schema 中 |
| `services/report_reflection.py` | 明确检查已写内容、原主题范围；材料后重申只返回结果结构；保留全研究一次修复预算 | 降低误报、自由文本返回和重复意见；无效反馈仍不视为通过 |
| `ResearchGap.topic_quote` | 要求从原用户主题逐字摘录需求依据，并删除有具体主题的提示词示例 | 防止把示例当成任务内容；字段引用存在不等于语义相关性已得到证明 |
| `services/research_constraints.py` | 识别明确的“报告是否提及/报告未提及”等模式 | 在评审接收、任务准备、查询改写和搜索恢复入口拦截明显无法通过外部检索回答的问题 |
| `graph/report_cycle.py` | 评审 reason 不再复制到任务 intent；保存实际停止原因和新增引用日志 | 防止把尚未核实的反馈作为摘要的事实前提 |
| `services/summarizer.py` | 增加可选 research_question 参数，补充任务使用干净问题与证据；报告自评输出整段拒绝 | 拒绝高光谱案例中“报告未提及 FCN [E编号]”这种证据错配；正常初始任务保留原调用方式 |
| `services/reporter.py` | 单列本轮补充任务结果和引用范围，说明逐项修订、资料不足与误报处理 | 让新材料可见，但不强制新增引用或编造内容 |
| `services/report_format.py` | 比较时忽略围栏外空行，保留有意义的文字、缩进、代码 | 停止只有排版变化的重复评审 |
| `report_iteration.py` / 前端 | 可缺省的 review_reused_from 字段，展示反馈来源版本 | 复用反馈不冒充新评审，段落编号仍能对应原版本 |

`ReviewSubmission.model_validate()` 校验模型返回的字典；`to_review()` 只在整体有效后转换为既有持久化结构。`extra="forbid"` 禁止把 query 塞进 revisions。不会删除冲突字段后假装模型已经正确理解问题。

`re.compile()` 编译的规则只识别明确的自评表达，不是通用语义分类器。泛化的误判、不同表达的错误反馈、外部来源不可靠、证据是否真的支持结论，仍需单独评测。不能把这层规则称为自动事实核查，也不能保证从此没有漏检或误拦。

无变化检测只忽略有限的排版差异；没有用删除全部空白的方式比较，避免把 `a b` 与 `ab`、代码中的空白变化当成相同。空白变化造成段落编号变化时，沿用反馈会明确指回原版本。

## 回归与兼容

真实失败 fixture 保存两版报告、三次原始评审输出、初始任务与证据、补充材料及错误摘要。测试不依赖用户当前数据库，也不请求网络。历史已完成报告、笔记和配置均不修改。

回归覆盖：旧自评问题不能创建任务；直接从 search 恢复也不会发出错误检索；错误查询改写回退；补充摘要照抄反馈时跳过且不保存为有效笔记；正常领域摘要仍可进入报告；空行变化不再次评审；数值、引用和代码变化仍被识别；冲突协议只能修复或未复核，不能伪装通过；原有失败恢复和引用流程继续可用。

## 冻结初稿对照

新入口 `evals.report_cycle_probe` 将同一份原报告作为关闭反思的 A 组，B 组从完全相同的任务、证据和正文开始执行真实报告反思。初始规划、搜索和报告生成不重复；需要补搜时仍调用实时搜索。每题使用独立目录和新 run_id，原研究不恢复、不修改。

```powershell
# backend 下执行，使用当前 .env 的模型和搜索配置
uv run python -m evals.report_cycle_probe tests/fixtures/report_cycle_hyperspectral.json

# 也可一次传入多个已有 evals 批次的 snapshot.json
uv run python -m evals.report_cycle_probe path/to/first/snapshot.json path/to/second/snapshot.json
```

目录保存 baseline.md、input.json、last_draft.md、report.md、iterations.json、state.json、checks.json 和 result.json。失败也记录已提交的状态。`quality_score` 固定留空，正文变化和新增引用只是诊断，不自动折算质量分。关闭反思的增量调用为零，不能把它当成整次研究零成本。
